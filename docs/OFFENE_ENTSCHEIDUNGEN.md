# Offene Entscheidungen

**Stand:** 26.10.2026 · **Quelle:** Analyse der Spezifikation in [`spezifikation/`](spezifikation/), siehe [`ENTWICKLUNGSPLAN.md`](ENTWICKLUNGSPLAN.md).

Regeln für dieses Dokument:

- Ein **Vorschlag** ist eine Empfehlung des Entwicklungsteams, **keine** fachliche Entscheidung. Er wird erst nach Freigabe umgesetzt.
- Nach einer Entscheidung den Status auf `entschieden` setzen und die Entscheidung mit Datum eintragen. Verbindliche fachliche Entscheidungen zusätzlich in `spezifikation/01_ANFORDERUNGEN.md` nachtragen.
- **blockiert** nennt die Phase, die ohne Entscheidung nicht abnahmefähig abgeschlossen werden kann.

## Mitarbeiter und Springer

**E40 – entschieden und umgesetzt (26.10.2026):** Mitarbeiter werden über die Linie durchnummeriert (T17 → Mitarbeiter 1, T18 → Mitarbeiter 2 …), und ein Mitarbeiter kann als Springer an mehreren Stationen arbeiten (F134). Nutzerentscheidungen: Arbeitsgänge eines Springers laufen nacheinander, auch über Stationen hinweg; keine Wegezeit; Verschieben auf eine andere Station entfernt den Mitarbeiter weiterhin (F61); Springer zählen bei der Mitarbeiterzahl je Station anteilig nach Belegung, im Szenario einmal. Im Import ist dieselbe Bezeichnung an mehreren Stationen dieselbe Person. Szenarien vor E40 rechnen unverändert (jede Spur eine eigene Person). Rechenregeln: [RECHENREGELN.md](RECHENREGELN.md), Abschnitt 6a. Datenbank: Migration `202610260004_springer.sql`.
